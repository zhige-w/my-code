## 执行与记录规则

- 在项目根目录使用 Python 3.11+ 的 .venv 执行验证。下列命令针对 task 中计划实现的测试，不在文档阶段执行。
- 每项仅实际验证通过后勾选，并在末尾记录检查编号、实际命令/操作、结果及脱敏证据。结果允许：通过、失败、未验收、不适用；失败或未验收需说明原因。
- pytest 必须实际收集并执行相关场景；未收集、跳过或依赖真实 API 的测试未运行时，不能记为相关能力通过。参数化场景需全部通过。
- 自动化模拟 SSE、Textual Pilot 和 tmux 真实 API 验收分别记录，不能互相冒充；任一必要子场景被阻塞时整项保持未勾选，记录已通过子场景与剩余项。
- 缺少 tmux、Python 运行环境、真实供应商凭据或模型权限时明确报告阻塞，继续可独立完成的检查；macOS/Linux 仅报告实际运行的平台，不声称未测试平台通过。
- 错误、截断或取消检查使用模拟 HTTP 或假 Provider，避免人为消耗真实 API 来触发异常；真实端到端场景必须在 tmux 中输入真实对话请求。
- 工具调用、文件操作和代码编辑等 Agent 能力本轮不适用，排除在通过数和未验收数之外；启动读取配置文件属于本轮范围。

1. 在项目目录运行 `.venv/bin/MyCode --config mycode.yaml --provider 实际供应商名`，观察进入全屏界面和状态栏。
