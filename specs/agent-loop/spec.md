## 背景

MyCode 是使用 Python 实现的终端 AI 编程助手，已有全屏终端界面、OpenAI Chat Completions 与 Anthropic Messages 流式对话、内存会话历史、Claude thinking 以及六个核心工具。

当前一轮对话只执行首次响应中的一批工具，再请求一次禁用工具的总结，无法根据工具结果继续操作。用户需要不断发送新请求才能推动多步骤任务。本轮引入 ReAct Agent Loop，让模型循环观察结果、调整行动并继续执行，直到完成或触发停止条件。

## 目标

- 将单批工具执行升级为“调用模型 → 执行工具 → 回写结果 → 继续判断”的自主循环。
- 通过独立异步事件流连接 Agent 与界面，提供文本、工具调用、工具结果、Token 用量和进度；文本实时展示，同时收集完整响应。
- 根据工具安全性安排并发与串行执行。
- 提供 `/plan` 只读规划与 `/do` 全工具执行两个阶段。
- 本轮不做权限系统、上下文压缩和交互式确认。

## 方案与选择

| 方案 | 优点 | 权衡 |
| --- | --- | --- |
| 独立 Agent Loop，通过异步事件连接界面（已选择） | 循环、历史和停止条件由 Agent 管理；界面负责展示与取消，符合解耦要求，便于独立测试 | 需要划分现有会话职责并接入事件消费 |
| 在现有 Conversation 中扩展循环 | 改动集中 | 需要重新划清对话历史与执行编排职责 |
| 先实现串行循环，再补并发与 Plan Mode | 单阶段范围更小 | 无法在本轮完成用户提出的全部能力 |

用户已选择第一种方案。本轮能力围绕同一执行链展开，完整纳入同一主题。

## 功能需求

- **F1 自主循环**：每次用户请求启动一次运行。完整响应包含工具调用时，执行并回写结果，再请求模型；没有工具调用时正常结束。工具失败作为结果交给模型，由模型决定如何调整。
- **F2 停止条件**：支持正常完成、达到迭代上限、用户取消、连续未知工具和模型流错误。每次 LLM 请求计一次迭代，默认上限为 20 次；到限后不执行该次响应中的工具。连续 3 个工具批次包含未知工具时，回写第三批结果后停止；不含未知工具的批次重置计数。停止原因明确展示，不自动重试模型请求。批次指一次完整模型响应中的全部工具调用；同批多个未知工具只计一个包含未知工具的批次。第 20 次响应没有工具调用时仍属于正常完成。
- **F3 异步事件流**：提供文本增量、公开思考增量、工具调用、工具结果、Token 用量、进度及运行结束事件。Agent 不依赖界面组件；界面通过事件展示当前迭代、执行状态与停止原因。每次运行恰好产生一个结束事件，之后不再产生事件。
- **F4 双路流式收集**：实时转发增量，同时收集完整响应供循环判断与历史保存。只有响应完整结束、工具参数与调用标识校验通过后，才能执行工具；中断响应保留展示，但不执行其中的调用。工具参数无效或调用 ID 缺失、重复时，不执行该响应中的任何工具，并明确报告异常。未知工具按 F2 回传错误结果并计数，不归入整批参数校验失败。
- **F5 安全批次执行**：`read_file`、`find_files`、`search_code` 可并发；`write_file`、`edit_file`、`execute_command` 串行。按模型调用顺序，将连续只读调用组成并发批次，副作用调用作为顺序屏障。例如“读 A、读 B、写 C、读 C”依次执行“并发读 A/B → 写 C → 读 C”。结果按原调用顺序回写，并保留调用 ID 配对。
- **F6 Plan Mode**：默认处于执行模式。`/plan` 切换为只读规划模式，后续请求仅开放三个只读工具；即使模型返回写入或命令调用，也拒绝执行并回传错误。规划完成后仍保持该模式。`/do` 切回执行模式，结合当前会话中的最近计划立即开始执行；没有计划时提示先规划或直接提交任务，不启动模型请求。生成期间不接受模式切换。规划模式同样使用 Agent Loop 及其停止条件。
- **F7 历史与取消一致性**：完整工具响应与每项实际结果进入历史，后续迭代可以引用。取消时停止活动工具、补齐未完成调用的取消结果，不启动下一次模型请求；已完成副作用不回滚。流错误后保留此前已提交的完整历史。未完成响应不作为完整回复保存。
- **F8 用量与进度**：展示当前迭代、迭代上限和本次运行累计 Token 用量。以供应商返回的用量为准；缺失时明确标为不可用，部分缺失时标记累计统计不完整，不记为零，也不估算费用。

## 非功能需求

- **N1 兼容性**：沿用 Python、现有终端界面、OpenAI Chat Completions 和 Anthropic Messages；保留普通聊天、流式文本、Claude thinking 及六个工具的现有能力。本轮循环与并发行为替代上一章的单批执行与单次总结限制。
- **N2 界面响应性**：模型流和工具执行期间，界面仍可滚动、编辑输入和取消。文本增量到达后及时展示，不等待完整响应或工具批次结束。
- **N3 并发有界**：只读工具并发上限默认 4 个，超出部分排队；副作用工具独占执行，不与其他工具重叠。沿用现有工具超时与输出大小限制。
- **N4 协议与历史一致性**：两个后端均保留工具调用与结果的 ID 配对及原生思考信息。每个已进入执行的调用恰好记录一个结果；并发完成顺序不改变历史中的调用顺序。
- **N5 可取消与资源清理**：取消覆盖模型流、排队工具和活动工具，关闭流连接并终止、回收工具进程；完成清理后恢复输入。涉及文件提交时，无法确认的副作用应明确提示，不误报为未执行。
- **N6 错误与隐私**：停止原因、工具错误及用量缺失均可观察；错误继续隐藏配置密钥，不新增请求、文件内容或命令输出的持久化日志。
- **N7 可测试性**：Agent 可脱离界面，使用可控模型流与工具验证循环、停止条件、事件顺序、并发屏障及 Plan Mode；测试结果区分模拟验证和真实模型验证。
- **N8 验收要求**：实现后执行相关自动化测试，并在 tmux 中启动 MyCode，输入真实请求，验证多轮自主工具调用及 `/plan → /do`，逐项记录 checklist 结果。缺少环境或凭据时明确记录未验收项。

## 不做的事

- **权限与交互式审批**：不新增工具授权弹窗、命令白名单或路径沙箱。Plan Mode 仅限制本模式可用的工具，不扩展为通用权限系统。
- **上下文管理**：不做上下文压缩、自动摘要、历史裁剪或会话持久化；上下文超限按模型请求错误停止。
- **自动重试与回滚**：不自动重试失败的模型请求或工具，也不撤销已完成的副作用。模型根据错误结果重新选择工具或调整参数，属于正常循环。
- **后台与多 Agent 执行**：不增加后台任务、持续交互式命令、任务委派或多个 Agent 协作；一次只运行一个用户任务，只读工具可在该任务内并发。
- **高级规划管理**：不增加计划编辑器、任务看板、计划持久化或逐步审批。计划保留在当前会话中，`/do` 根据最近计划执行；规划完成不自动进入执行模式。
- **额外停止策略**：本轮不增加总耗时、Token 预算、费用预算或重复调用检测等停止条件；保留已确认的迭代上限、连续未知工具停止，以及现有请求和工具超时。
- **新增工具与协议**：沿用六个核心工具和两个现有模型协议，不接入 MCP、插件工具、Responses API 或新增供应商。
- **额外统计与平台能力**：不做费用估算、跨会话用量统计、多模态或 Windows 验收。

## 验收标准

- **AC1 → F1**：模型先调用工具，再根据结果发起下一批调用，最后输出无工具调用的回复；整个过程无需用户催促。普通文本回复只请求模型一次。
- **AC2 → F2**：分别验证正常完成、迭代到限、用户取消、连续未知工具和流错误，均展示明确停止原因，停止后不再发起模型请求或工具执行。默认最多请求模型 20 次，第 20 次响应中的工具不执行。
- **AC3 → F2**：连续 3 个工具批次包含未知工具时，第三批结果回写后停止；其中插入不含未知工具的批次会重置计数。普通工具失败不会误触发此条件。
- **AC4 → F3**：无需启动界面即可消费 Agent 异步事件，观察文本、工具调用、工具结果、用量、进度和结束事件；每次运行恰好产生一个结束事件，完成后不再产生事件。
- **AC5 → F4**：文本碎片到达时即展示，完整响应保留全部文本和工具参数。流截断、参数无效或调用 ID 缺失、重复时，不执行该响应中的工具，并明确报告异常。
- **AC6 → F5、N3**：连续只读调用可以重叠执行，活动工具数最多为 4；副作用调用独占执行。验证“读 A、读 B、写 C、读 C”按“并发读 A/B → 写 C → 读 C”执行，结果按原调用顺序回写。
- **AC7 → F6**：`/plan` 后仅向模型提供三个只读工具；模型越界请求写入或命令执行时，返回拒绝结果，文件和命令均未执行。规划结束后仍保持规划模式。
- **AC8 → F6**：已有计划时输入 `/do`，切回全工具并立即执行最近计划；没有计划时给出提示，不启动模型请求。生成期间切换模式被拒绝，当前任务模式保持不变。
- **AC9 → F7、N4、N5**：在模型流、并发只读工具和副作用工具执行期间分别取消，活动资源得到清理，排队调用不启动，已进入执行阶段的每个调用都有唯一结果。已完成副作用保留，结果不确定时明确提示；清理后可发送新请求。
- **AC10 → F7**：后续迭代和下一次用户请求能够引用已提交的工具结果；后续流错误或取消不丢失此前完整历史，也不将未完成响应保存为完整回复。两个后端的调用 ID 配对、原生思考信息均保持正确。
- **AC11 → F8**：进度显示当前迭代和上限；累计 Token 用量与供应商返回值一致。部分或全部用量缺失时明确标记统计不完整或不可用，不将缺失值当作零，不显示估算费用。
- **AC12 → N1、N2、N6**：普通聊天、多轮对话、Claude thinking 和六个工具无回归；运行期间可滚动、编辑输入和取消；错误展示隐藏配置密钥，不新增敏感内容持久化日志。
- **AC13 → N7、N8**：相关自动化测试通过；在 tmux 中启动真实 MyCode，通过真实模型请求验证多批自主调用和 `/plan → /do`，对照 checklist 记录证据。未执行、失败和环境阻塞项分别列明。

- 边界清晰：未知工具错误可回传并计数；无效参数按 AC5 阻止该响应整批执行；普通执行失败回传模型，不自动重试。工具受模式限制时拒绝执行并回传错误。

- 验收可观察：循环请求数、工具执行顺序、停止原因、事件、模式限制、历史、用量及资源清理均可通过运行和观察验证；真实 tmux 场景独立记录，不以模拟测试替代。
