## 验收与记录规则

- 四份文档全部获批后执行，检查项只有实际验证通过才能勾选。状态分为通过、失败、未执行、环境阻塞；后三种均保持未勾选，并在实际结果记录中说明。
- 自动化验证执行 task 中相关 pytest 命令；测试必须实际收集并执行，跳过或无匹配不算通过。下文描述的是行为，测试文件路径是当前执行入口，重构时可更新入口而不改变预期行为。
- 可控模型、模拟 SSE、本地真实工具与真实模型 tmux 结果分别标注，不能相互替代。双协议模拟测试与实际网关/模型能力分别报告。
- 证据限于本主题 `specs/agent-loop/evidence/`，保存脱敏命令结果、终端画面及受控文件对比；不持久化真实凭据或无关文件内容，不覆盖上一主题报告。
- 每项记录检查编号、状态、实际观察、验证命令、证据位置、实际协议/模型（适用时）。失败修复后重跑受影响项，保留失败与修复后结果的区别。
- 缺少 tmux、运行环境、真实凭据或本轮 checklist 时明确阻塞；实际未配置的协议和原生 Claude thinking 真实能力不宣称通过。
- C58–C63 必须按实际配置分别记录 openai 与 anthropic 的真实运行结果；缺少其中一个时保留该协议的未验收记录，不以另一个协议的结果替代。
